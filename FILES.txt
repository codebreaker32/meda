meda-gnn-routing: what every file does
=======================================

Reimplementation of Elfar et al., "Deep Reinforcement Learning-Based Approach
for Efficient and Reliable Droplet Routing on MEDA Biochips", IEEE TCAD 42(4),
2023, as the base for GNN-based routing (B.Tech project).

How the pieces fit together, in the order a training run uses them:

  configs/*.yaml  ->  training/config.py      (read settings)
                  ->  envs/meda_env.py         (simulated chip = core/*)
                  ->  agents/cnn.py            (policy network: the paper's CNN)
                      or representations/graph_builder.py + agents/gnn.py
                                               (the project's GNN: graph -> GCN -> max pooling)
                  ->  training/trainer.py      (PPO epochs, evaluation, saving)
                  ->  runs/<name>/seed_<s>/    (models, checkpoints, logs, plots)
  trained model   ->  routers/drl.py           (use it as a router)
                  ->  routers/compare.py, bioassay/*   (benchmarks vs. baselines)
                  ->  viz/*                    (figures and GIFs)
  CNN and GNN runs -> experiments/method_comparison.py (`meda compare-methods`)
                  ->  results/tables, results/logs, results/figures

Parameter sources: every setting in the code and configs is tagged
  [PAPER ...]  value stated in the paper (section / figure / table)
  [REF-CODE]   not in the paper; from the authors' public code melfar87/MEDA
  [METHOD-DOC] specified by the project's GNN methodology document
               (docs/GNN_METHODOLOGY.md), not by the paper
  [ASSUMED]    chosen by us
docs/IMPLEMENTATION_NOTES.md explains each non-paper decision in detail.

src/meda_routing/  (the code; installed as the Python package)
-----------------
__init__.py               Package summary and version.
__main__.py               Makes `python -m meda_routing ...` equal to `meda ...`.
cli.py                    The `meda` command: train, curriculum, evaluate,
                          compare, bioassay, plot-training, render, devices.
                          Decides default output locations (next to the model).
devices.py                Picks the compute device: local CUDA GPU with the most
                          free memory, else Apple MPS, else CPU; MEDA_DEVICE
                          overrides. `meda devices` prints the choice.
paths.py                  Finds the project folder and the runs folder
                          (<project>/runs or $MEDA_RUNS_DIR) so all outputs of
                          a run stay together whatever the working directory.

core/  - the physical model of a MEDA biochip (Sec. II-III of the paper)
  geometry.py             Rect / Droplet: rectangles of microelectrodes (MCs)
                          as (xa, ya, xb, yb), distances, footprints.
  actions.py              The 8 actions (N, S, E, W, NE, NW, SE, SW) and
                          Algorithm 1: adaptive step size floor(size/2), never
                          overshooting the goal.
  biochip.py              MEDABiochip: per-MC degradation D = tau^(n/c)
                          (Eq. 1), b-bit health sensing H = floor(2^b D), wear
                          counters, injected faults and hidden defects.
  movement.py             Probabilistic droplet movement: a step succeeds with
                          the mean degradation of the frontier MCs; exact
                          outcome distributions; valid/invalid actions.
  dynamics.py             One control cycle: plan the actuation pattern for an
                          action, execute it (random outcome), update wear.
  jobs.py                 Routing jobs (start, goal, routing zone), the
                          paper's 9 droplet sizes, stratified / uniform job
                          sampling, hazard (routing-zone) bounds.

envs/  - the reinforcement-learning environment (Sec. III, Algorithm 2)
  meda_env.py             MEDARoutingEnv (Gymnasium "MEDA-Routing-v0") and its
                          EnvConfig: samples a job and a chip each episode,
                          steps the dynamics, returns observation / reward,
                          ends at the goal or after k_max cycles. Also the
                          persistent-chip mode (online adaptation) and
                          render_frame for GIFs.
  observation.py          The 3-channel image observation (health masked to
                          the routing zone, droplet, goal), resized to 30x30.
  reward.py               The reward: progress towards the goal, +100 at the
                          goal, penalties for stalling and invalid actions.

agents/  - policy networks = state encoders for PPO
  cnn.py                  MedaCNN: the Table I CNN (3x3 conv 64/128/128, FC 256)
                          used as the shared feature extractor of PPO (baseline).
  gnn.py                  MedaGNN ("gnn" / "gnn_maxpool"): the proposed encoder.
                          GCN message passing over the 8-neighbour MC graph
                          (sparse matrix products, runs on GPU), then a graph
                          readout; "dir_gcn" = direction-aware ablation.
  graph_readout.py        Node embeddings -> graph embedding: global max pooling
                          (default), mean, sum, role-aware (droplet/goal).
  registry.py             Name -> feature-extractor registry; register further
                          architectures here and select them with
                          agent.extractor=<name>.

representations/  - how an observation is presented to a network
  graph_builder.py        Observation (3, H, W) -> graph: one node per MC
                          (node = y*W + x), the 3 baseline features per node,
                          8-neighbour edges in both directions, no edge
                          attributes; validate_graph() = the methodology's
                          checks (node count, adjacency, feature parity, ...).

experiments/  - studies built on the reproduced baseline
  method_comparison.py    `meda compare-methods`: evaluates CNN-PPO and
                          GNN-PPO runs (all seeds) on the same held-out jobs
                          and writes experiment_config.csv, main_comparison.csv,
                          per_seed_results.csv, graph_validation.csv,
                          training_metrics.csv, evaluation_jobs.csv and figures.

training/  - PPO training (Sec. IV-B/C)
  config.py               TrainConfig and its sections (agent, ppo, schedule,
                          eval) with tagged defaults; YAML loading and
                          `--set key=value` overrides.
  trainer.py              Trainer: builds PPO on the chosen device, trains
                          epoch by epoch, evaluates on 500 jobs, applies the
                          LR rule, saves model.zip / best_model.zip /
                          checkpoints/epoch_XXX.zip / progress.csv /
                          summary.json / training_curves.png.
  lr_schedule.py          The dynamic learning-rate scheduler (eta_0 = 3.5e-4,
                          x0.7 when success > 99%, floor 1e-6).
  evaluation.py           Runs a model on N jobs: success/failure rate, score,
                          mean/median/std cycles, invalid-action rate, and
                          optionally one record per job.
  curriculum.py           Chains of trainings: traditional learning (random
                          init per size) and transfer learning (init from the
                          previous agent), Fig. 3.

routers/  - routing policies behind one interface, for comparisons
  base.py                 Router interface, RoutingState, run_job (route one
                          droplet on a given chip and record the result).
  drl.py                  DRLRouter: wraps a trained model (CNN or your GNN).
  baseline.py             Health-agnostic shortest-path router (single,
                          double or adaptive steps) - the paper's baseline.
  formal.py               "Formal" router: exact MDP-optimal strategy on the
                          sensed health map (stands in for PRISM-games).
  compare.py              Runs several routers on identical jobs and chips and
                          summarizes success rate, cycles and speed (Sec. VI).

bioassay/  - whole bioassays with many droplets (Sec. V-B, Fig. 9)
  library.py              COVID-RAT (28 operations) and COVID-PCR (34
                          operations) sequence graphs, from the reference code.
  scheduler.py            BioassayExecutor: runs all concurrent routing jobs of
                          a bioassay on one aging chip, cycle by cycle.
  benchmark.py            Repeated trials on pre-aged chips, completion-time
                          statistics and the P(completion <= k) curve.

viz/  - figures and animations
  plots.py                Training curves (Figs. 4/7/8 style), completion CDFs
                          (Fig. 9), routing paths (Fig. 14), router comparison
                          bars.
  animation.py            record_episode: GIF of a droplet being routed, with
                          cycle counter and trail.


configs/  - experiment settings (every value tagged with its source)
-------
training/paper_30x30_healthy.yaml   H(30,0%): the paper's base agent, all
                                    defaults written out. Start here.
training/paper_30x30_faults10.yaml  H(30,10%): 10% injected faults, starts
                                    from the healthy agent (Fig. 8).
training/covid_60x30.yaml           Agent for the 60x30 bioassay chip (Fig. 9).
training/online_adaptation_30x30.yaml
                                    Keeps training on one aging chip (Sec. I).
training/quick_cpu_30x30.yaml       Smaller CNN and shorter evaluation, for
                                    laptops without a GPU.
training/reference_0825a_30x30.yaml Mirrors the authors' logged training run.
training/validation_16x16.yaml      Small 16x16 problem used to check learning
                                    on a CPU (docs/RESULTS.md section 6); also
                                    the CNN side of the CPU-sized comparison.
training/gnn_maxpool_30x30.yaml     GNN + max pooling + PPO: inherits the CNN
                                    baseline (base: paper_30x30_healthy.yaml)
                                    and changes only the encoder.
training/gnn_maxpool_16x16.yaml     The same on 16x16 (base: validation_16x16.yaml).
training/gnn_dirgcn_<size>.yaml     Ablation: direction-aware message passing
                                    (gnn_type: dir_gcn), everything else as
                                    gnn_maxpool_<size> (best result so far).
training/gnn_role_<size>.yaml       Ablation: role-aware readout (pooling: role).
curricula/transfer_learning.yaml    Fig. 3(b)/4/8: 30 -> 60 -> ... -> 180 and
                                    0% -> 10% -> 20% faults.
curricula/traditional_learning.yaml Fig. 3(a)/4/7: every size from scratch.


scripts/
-------
run_gnn_experiment.sh     The whole CNN vs. GNN experiment: graph checks, both
                          trainings (same settings and seeds), comparison.
                          SIZE=16 SEEDS=1 for a CPU-sized run.
run_on_gpu_server.sh      Runs any `meda` command on a GPU server of the
                          network (e.g. GPU_SERVER=user@192.168.1.50): copies
                          the code, sets up a virtualenv, runs, copies runs/
                          back; runs locally if the server is unreachable or
                          has no GPU. `status` and `fetch` for long runs.
gpu_server.env.example    Template for the server settings (copy to
                          scripts/gpu_server.env).
reproduce_paper.sh        All paper experiments in one go (GPU recommended);
                          QUICK=1 for a smoke-size run.
evaluate_reference_model.py
                          Loads the authors' trained TensorFlow agent into
                          PyTorch and runs it in our environment (validation);
                          --shortest-path runs the optimal router instead.
compare_with_reference_log.py
                          Reads the authors' training log and compares it with
                          one of our progress.csv files.


examples/
--------
gnn_extractor_example.py  A small working GNN feature extractor (grid graph,
                          mean aggregation) registered as "gnn_example": the

__init__.py               Makes examples/ importable (--import-module).


docs/
----
IMPLEMENTATION_NOTES.md   Paper -> code map and the table of every decision
                          the paper leaves open (paper / reference code / ours).

                          reward check, router comparisons, bioassays, runtime,
                          16x16 training run.
